# APS 回调安全签名规范（HMAC-SHA256）

> 对应任务：P0-12
> 模块路径：`mes-framework/security/HmacSignatureFilter`
> 影响范围：`POST /api/aps/callback/**`

---

## 1. 背景

`ApsCallbackController` 接收外部 APS 系统的排程结果回调，路径位于 `/aps/callback/**`。该路径在 `SecurityConfig.PUBLIC_URLS` 中处于 `permitAll` 状态（无 JWT 校验），若缺少签名校验，任何外部请求都可伪造回调写入排程结果。

**目标**：在不改变 APS 端无状态调用模式的前提下，引入 HMAC-SHA256 + 时间戳 + API Key 的三重签名校验。

---

## 3. 请求头定义

| Header | 类型 | 是否必填 | 说明 |
|---|---|:---:|---|
| `X-API-Key` | string | 是 | 对端 APS 的 API Key，由 MES 侧配置项 `mes.aps.api-key` 统一登记 |
| `X-Timestamp` | long | 是 | Unix 时间戳（秒或毫秒均可；服务端按位数自动识别） |
| `X-Signature` | hex string | 是 | HMAC-SHA256 输出的小写十六进制，长度 64 字符 |

---

## 4. 签名算法

```
message   = apiKey + "\n" + timestamp + "\n" + rawBody
signature = lowercase( hex( HMAC-SHA256(message, hmacKey) ) )
```

关键点：

1. **拼接字符**固定为 `\n`（ASCII 0x0A），不要使用 `\r\n`。
2. `rawBody` 是 HTTP 请求体的**原始字节流**，未经任何反序列化；`GET` 类请求 body 为空字节数组。
3. `hmacKey` 来自服务端配置 `mes.aps.hmac-key`，**生产环境强制 &ge; 32 字节**。
4. 最终签名必须**小写**，使用常量时间比对（`MessageDigest.isEqual`）避免时序攻击。

## 5. 服务端配置

### 5.1 `application.yml`

```yaml
mes:
  aps:
    api-key: ${MES_APS_API_KEY:mes-default-api-key}
    hmac-key: ${MES_APS_HMAC_KEY:}
    timestamp-skew-seconds: 300
    enabled: true
```

### 5.2 启动期 fail-fast 校验

`HmacSignatureFilter#validateConfig` 在 `@PostConstruct` 阶段执行：

| 条件 | 开发环境（profile=dev 或未指定） | 生产环境 |
|---|---|---|
| `mes.aps.enabled=false` | 全面放行并告警 | 全面放行并告警（不推荐） |
| `mes.aps.hmac-key` 为空 | 放行 + WARN 日志 | **启动失败** |
| `mes.aps.hmac-key.length < 32` | 放行 + WARN 日志 | **启动失败** |
| `mes.aps.api-key` 为空 | WARN 日志，签名必然失败 | WARN 日志，签名必然失败 |

### 5.3 生产部署 env 注入

```bash
export MES_APS_API_KEY="$(openssl rand -hex 16)"        # 32 hex chars
export MES_APS_HMAC_KEY="$(openssl rand -hex 32)"       # 64 hex chars，满足 >=32 bytes
```

把两个变量下发到 MES 侧的容器/环境；同值下发到 APS 侧用于签名。

## 6. APS 调用方示例（curl）

假设：

- `apiKey = "APS-PROD-KEY-001"`
- `hmacKey = "3f8b2c1a9d5e7f0c4b8a6d2e9f1c3b5a7d9e0f2c4b6a8d0e2f4c6b8a0d2e4f6c"`
- `timestamp = 1713693600`（秒）
- 请求体 `{"requestId":"REQ-001","items":[{"id":1,"start":"2026-04-21T08:00:00"}]}`

### 6.1 生成签名（Bash + openssl）

```bash
API_KEY="APS-PROD-KEY-001"
HMAC_KEY="3f8b2c1a9d5e7f0c4b8a6d2e9f1c3b5a7d9e0f2c4b6a8d0e2f4c6b8a0d2e4f6c"
TS=$(date +%s)
BODY='{"requestId":"REQ-001","items":[{"id":1,"start":"2026-04-21T08:00:00"}]}'

MESSAGE=$(printf '%s\n%s\n%s' "$API_KEY" "$TS" "$BODY")
SIG=$(printf '%s' "$MESSAGE" | openssl dgst -sha256 -hmac "$HMAC_KEY" -hex | awk '{print $2}')

curl -X POST https://mes.example.com/api/aps/callback/schedule-result \
     -H "Content-Type: application/json" \
     -H "X-API-Key: $API_KEY" \
     -H "X-Timestamp: $TS" \
     -H "X-Signature: $SIG" \
     --data-raw "$BODY"
```

### 6.2 Java 侧生成签名

```java
String message = apiKey + "\n" + timestamp + "\n" + body;
Mac mac = Mac.getInstance("HmacSHA256");
mac.init(new SecretKeySpec(hmacKey.getBytes(StandardCharsets.UTF_8), "HmacSHA256"));
byte[] digest = mac.doFinal(message.getBytes(StandardCharsets.UTF_8));
String signature = HexFormat.of().formatHex(digest);   // lowercase hex
```

## 7. 失败响应

所有校验失败返回 HTTP 401：

```json
{
  "code": 401,
  "message": "APS 回调签名不匹配",
  "data": null
}
```

可能的 `message`：

| 场景 | message |
|---|---|
| 缺必填头 | `APS 回调缺少必要请求头 X-API-Key / X-Timestamp / X-Signature` |
| API Key 错 | `APS 回调 API Key 非法` |
| timestamp 非数字 | `APS 回调 X-Timestamp 非法，需为 Unix 秒或毫秒整数` |
| 时间偏差大 | `APS 回调时间戳偏差超过允许范围` |
| 签名不匹配 | `APS 回调签名不匹配` |

## 8. 验证用例

| 用例 | 请求构造 | 期望结果 |
|---|---|---|
| V1 正常签名 | 使用约定 secret + 正确 body | 200 OK，业务处理成功 |
| V2 缺 X-Signature | 头只带 apiKey / timestamp | 401 + `缺少必要请求头` |
| V3 API Key 错误 | apiKey 改为随机串 | 401 + `API Key 非法` |
| V4 时间偏差 10 分钟 | timestamp = now - 600 | 401 + `时间戳偏差超过允许范围` |
| V5 body 被改动 | body 与签名时不一致 | 401 + `签名不匹配` |
| V6 大小写 signature | hex 使用大写 | 401（服务端仅接受小写；对端请用 lowercase） |
| V7 毫秒时间戳 | timestamp = now×1000 | 200 OK（自动识别位数） |
| V8 重放攻击（5 分钟外） | 正确签名但 timestamp 过期 | 401 + `时间戳偏差超过允许范围` |

> 注：当前实现没有做 nonce 幂等表，5 分钟内的重放请求会被接受；如需要完整重放防御，建议下一期在 Redis 存 `nonce:{apiKey}:{timestamp}:{sig}` 并设 TTL=300s。
