# APS 集成接口契约

## 1. 概述

本文档定义 MES 系统与 APS（Titan APS）系统之间的接口契约，包括下行接口（APS → MES）、上行接口（MES → APS）以及统一错误码。

### 1.1 通信协议

- 协议：HTTP/HTTPS
- 数据格式：JSON
- 字符编码：UTF-8
- 时间格式：ISO 8601（`yyyy-MM-dd'T'HH:mm:ss`）
- 认证方式：API Key（通过请求头 `X-API-Key` 传递）

### 1.2 APS 系统基础信息

| 项目 | 说明 |
|------|------|
| APS 基础 URL | `http://{aps-host}:{aps-port}` |
| API 前缀 | `/api` |
| 版本 | 单体版 Titan APS |
| 响应格式 | `ApiResponse<T>` |

### 1.3 统一响应格式

```json
{
  "code": 200,
  "message": "操作成功",
  "data": { }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| code | int | 状态码：200 成功，400 参数错误，500 服务器错误 |
| message | string | 提示信息 |
| data | T | 响应数据 |

## 2. 下行接口（APS → MES）

MES 通过定时任务主动从 APS 拉取数据。

### 2.1 获取排程订单列表

**用途**：MES 定时从 APS 拉取已排程的订单数据，同步到 MES 订单计划。

**请求**

```
GET /api/orders?status=SCHEDULED&page=0&size=200
```

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| status | String | 否 | - | 订单状态筛选：PENDING/SCHEDULED/LOCKED |
| page | Integer | 否 | 0 | 页码（从 0 开始） |
| size | Integer | 否 | 200 | 每页大小 |

**响应**

```json
{
  "code": 200,
  "data": {
    "content": [
      {
        "id": 1,
        "orderNo": "ORD001",
        "itemId": 5,
        "itemName": "蓝色单车",
        "itemCode": "ITEM-001",
        "quantity": 100,
        "dueDate": "2026-05-01T08:00:00",
        "earliestStartTime": "2026-04-01T08:00:00",
        "priority": 1,
        "status": "SCHEDULED",
        "orderType": "FORMAL"
      }
    ],
    "totalElements": 50,
    "totalPages": 1,
    "number": 0,
    "size": 200
  }
}
```

**响应字段说明**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Long | APS 订单 ID |
| orderNo | String | 订单编号（全局唯一，MES 关联键） |
| itemId | Long | APS 物料 ID |
| itemName | String | 物料名称 |
| itemCode | String | 物料编码（用于 MES 映射） |
| quantity | Integer | 计划数量 |
| dueDate | String | 交货期（ISO 8601） |
| earliestStartTime | String | 最早开始时间 |
| priority | Integer | 优先级（数字越小优先级越高） |
| status | String | 订单状态：PENDING/SCHEDULED/LOCKED |
| orderType | String | 订单类型：FORMAL（正式）/FORECAST（预测） |

## 3. 上行接口（MES → APS）

MES 主动将执行数据推送给 APS。

### 3.1 更新订单状态

**用途**：MES 工单状态变更后，同步到 APS 订单状态。

**请求**

```
PUT /api/orders/{id}/status
```

**请求体**

```json
{
  "status": "LOCKED"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| status | String | 是 | 目标状态：PENDING/SCHEDULED/LOCKED |

**MES 到 APS 状态映射**

| MES 事件 | APS 操作 | 说明 |
|----------|----------|------|
| 工单开工 | `PUT /api/orders/{id}/lock` | 锁定订单，防止 APS 重排变动 |
| 工单完工 | `PUT /api/orders/{id}/status` → PENDING + 标记完成 | 释放资源 |
| 工单强制完工 | 同上 | 同上 |
| 工单终止 | `PUT /api/orders/{id}/status` → PENDING | 释放资源 |

**响应**

```json
{
  "code": 200,
  "message": "状态更新成功"
}
```

## 6. 重试策略

### 6.1 重试机制

| 重试次数 | 等待时间 | 说明 |
|----------|----------|------|
| 第 1 次 | 5 秒 | 短暂网络抖动 |
| 第 2 次 | 15 秒 | 服务临时不可用 |
| 第 3 次 | 30 秒 | 最后一次尝试 |
| 超过 3 次 | - | 标记为失败，等待人工处理或下次定时任务 |

### 6.2 幂等性保证

- 所有上行同步接口通过 `syncBatchId` 保证幂等
- 相同 `syncBatchId` 的重复请求返回成功但不重复处理
- 下行拉取通过 `updated_time` 增量查询保证不重复同步

### 6.3 限流策略

- 单次同步批量上限：200 条
- 同步接口调用频率：不超过 12 次/分钟
- 异常重排触发频率：相同类型异常 5 分钟内仅触发一次
